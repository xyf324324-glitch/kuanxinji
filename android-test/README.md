# 宽心纪安卓安装测试版

当前为独立测试分支 `codex/android-apk`，不修改正式网站主分支，不发布公开 APK 下载入口。

## 功能与结构

- Android 8.0（API 26）及以上，Java / WebView / 系统本地通知，不依赖 Google Play Services、FCM 或浏览器 Web Push。未包含特定 CPU 架构的 native 库。
- 测试包名 `dev.kuanxinji.preview`，名称“宽心纪测试版”，避免与今后正式版混淆。
- 加载 `https://codex-android-apk.kuanxinji.pages.dev/`，测试分支页面部署后应用下次加载可获取新页面；网站仍可能显示自己的内容更新提示。不会把本地静态打包误称为在线更新。
- AndroidX WebMessageListener 仅对编译时指定的 HTTPS 页面 origin 注入桥接对象，只接受主框架请求；外部链接交给浏览器。不开启文件读取，不忽略 SSL 错误，不给任意第三方页面原生接口。
- 默认念佛 09:00 / 21:00，一念回光 09:00 / 13:00 / 21:00，同刻合并。可添加、删除、修改时间及恢复默认；修改时取消原排程。
- 系统通知权限和 Android 12+“闹钟和提醒”权限确认后才显示启用成功。通知正文在锁屏是否可见由用户系统设置决定。
- 使用 AlarmManager 本地安排，不要求页面保持打开。重启、时区 / 时间变化、应用覆盖更新后重新安排。用户强行停止应用、关闭权限或厂商后台限制仍可能影响提醒。
- “发送测试通知”安排约一分钟后的本地通知；站内通用文案提示约两分钟内，给出等待余量。
- 启动和设置中的“检查安装包更新”读取同源 `/android/version.json`。当前版本 1，无新 APK 发布。未来 APK 更新需更高 versionCode 和受限制的 HTTPS 下载链接，由用户确认下载 / 安装，不支持静默安装。

## 云端构建

GitHub Actions `Android test APK` 使用 Ubuntu 24.04 已有的 Android 工具、JDK 17、Gradle 8.11.1、AGP 8.9.2。执行客户端测试、Java 单元测试、Android Lint、assembleDebug、APK 签名验证和 SHA-256 校验。无需在用户电脑安装 SDK、Android Studio 或模拟器。

构建仅由本仓库测试分支推送 / 手动触发；不读取网站服务端密钥。测试签名使用 runner 生成的 debug key，并通过 Actions 缓存复用；这不是正式发布密钥，缓存丢失后不能保证测试 APK 之间可覆盖安装。正式公开分发前必须另配持久且私有的签名密钥。不要把测试签名当作生产签名。

## 小米安装与验收

1. 将 APK 复制到手机，手动确认安装。安装后显示“宽心纪测试版”。通过微信传文件若扩展名被改为 `.apk.1`，在文件管理器中恢复为 `.apk` 后打开。
2. 打开应用，开启每日提醒并允许系统通知；若出现“闹钟和提醒”说明，进入系统设置允许后返回。
3. 在导航“每日提醒”发送测试通知，锁屏等待约 1–2 分钟；收到后再测切到其他应用时的展示。
4. 把两个项目设置为同一个接下来几分钟的时间并保存，确认只收到一条合并通知；再改时间，确认旧时刻不再触发。
5. 开启后断网验证提醒；重启手机后再次设置近期时间测试。分别记录普通后台、省电模式和系统“强行停止”的行为，不能把它们视为同一种状态。
6. 关闭提醒后，确认排程停止；检查恢复默认仅在保存后生效。

构建和自动检查通过不等于真机提醒已验收。本次尚未连接安卓真机；需要用户在手机完成收件验证。
